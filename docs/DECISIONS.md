# Decisiones de arquitectura (ADR)

Formato: decisión · motivo. Añadir al final con `/handoff` cuando se decida algo nuevo (3 líneas).

| #      | Decisión                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Motivo                                                                                                                                                          |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ADR-1  | React (no Vue)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Ecosistema, soporte de Capacitor y de Claude Code. Confirmada.                                                                                                  |
| ADR-2  | Supabase (no Firebase)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | PostgreSQL relacional, RLS, modelo de datos relacional.                                                                                                         |
| ADR-3  | Solo el backend habla con DeepSeek                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Protege la API key, centraliza costos, permite cambiar de proveedor.                                                                                            |
| ADR-4  | Interfaz `AiProvider` + adaptador `DeepSeekProvider`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Aísla el riesgo del modelo y facilita pruebas con simulados.                                                                                                    |
| ADR-5  | La IA responde solo JSON, validado con Zod; un reintento                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | La salida de un LLM no es confiable.                                                                                                                            |
| ADR-6  | Imagen comprimida en el cliente (768 px, JPEG ~0,7)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Menos latencia, costo y datos móviles.                                                                                                                          |
| ADR-7  | El contenedor lo decide `disposal_rules`, no la IA                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Las reglas cambian por municipio.                                                                                                                               |
| ADR-8  | Escanear sin cuenta; historial y favoritos con cuenta (correo verificado o Google)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Menos fricción en el primer uso.                                                                                                                                |
| ADR-9  | Backend en Railway (Docker), frontend en Vercel                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Decisión del equipo; HTTPS automático en ambos.                                                                                                                 |
| ADR-10 | Monorepo con workspaces `shared` + `backend`; `frontend` se añade en F2                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | Contrato único sin duplicar tipos.                                                                                                                              |
| ADR-11 | `max_tokens` 384 en escaneos; 512 en chat (`DEEPSEEK_CHAT_MAX_TOKENS`, ajustable)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | 384 es poco para pasos de fabricación; se valida en F0/F3.                                                                                                      |
| ADR-12 | Ramas por historia + `STATUS.md` como memoria entre sesiones                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Metodología de contexto (`METODOLOGIA-CONTEXTO.md`).                                                                                                            |
| ADR-13 | DeepSeek con `thinking: { type: 'disabled' }` en escaneos y chat                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | El razonamiento consume `max_tokens` y truncaba el JSON; más rápido y barato.                                                                                   |
| ADR-14 | `createApp()` crea el `DeepSeekProvider` de forma perezosa y un rate limiter por instancia                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Health y pruebas sin `DEEPSEEK_API_KEY`; cada prueba con su contador.                                                                                           |
| ADR-15 | `disposal_rules` en caché por instancia (TTL 10 min; ante fallo, caché vencida y reintento al minuto; sin caché → `disposal: null`). Con certeza < 0,60 solo se devuelve `disposal` si `requiresDropOff`                                                                                                                                                                                                                                                                                                                                                                                | Supabase caído no rompe la clasificación; ante la duda, pilas y electrónicos nunca van al contenedor doméstico.                                                 |
| ADR-16 | Cualquier fallo de `image` (Zod o `assertValidImage`) → `INVALID_IMAGE`, con prioridad sobre otros campos; `alternatives` las normaliza el backend (sin el principal ni repetidos, ordenadas, máx. 2; la IA tolera 4)                                                                                                                                                                                                                                                                                                                                                                   | Un solo código para que el cliente ofrezca «Repetir foto»; no se depende de que la IA cumpla el formato.                                                        |
| ADR-17 | El frontend lee `shared` por alias de Vite y `paths` de tsconfig (no dependencia `"*"`); `zod` es dependencia directa del frontend y `shared/tsconfig.json` es autónomo                                                                                                                                                                                                                                                                                                                                                                                                                 | Vercel puede construir solo con `frontend/` y `shared/`, sin la raíz; verificado en una copia aislada (pruebas + build que importa `src/api`).                  |
| ADR-18 | Configuración que falla pronto: el build de producción del frontend exige `VITE_API_URL` absoluta (el CI usa `http://localhost:3000`) y `server.ts` termina con código 1 en producción si faltan `DEEPSEEK_API_KEY`, `SUPABASE_URL` o `SUPABASE_SERVICE_ROLE_KEY` (solo registra nombres)                                                                                                                                                                                                                                                                                               | Un secreto vacío solo se notaba como 500 al escanear; mejor un despliegue fallido en Railway/Vercel que una app rota en producción.                             |
| ADR-19 | La foto se comprime en el cliente (`compressImage.ts`: 768 px, JPEG 0,7 → 0,5 hasta ≤ 300 KB, EXIF por `createImageBitmap`) y llega a `/resultado` por `photoStore` (Zustand, sin el `Blob` original); la cámara se apaga al tener foto y se reabre con Repetir                                                                                                                                                                                                                                                                                                                         | Una foto de teléfono supera los 4 MB del contrato; apagar la cámara ahorra batería y evita el video pausado al volver.                                          |
| ADR-20 | En el resultado, `requiresDropOff` tiene prioridad sobre la baja certeza (se muestra el punto limpio con el aviso «No estoy seguro» encima) y la certeza se muestra truncada (`Math.floor` con tolerancia 1e-9)                                                                                                                                                                                                                                                                                                                                                                         | Pilas y electrónicos nunca deben acabar en un contenedor doméstico por una duda; un «60 %» redondeado contradiría al umbral de 0,60.                            |
| ADR-21 | Las instrucciones de `disposal_rules` valen para cualquier objeto del material (no asumen un envase); las migraciones de datos filtran por el texto anterior (`where instructions = '<viejo>'`)                                                                                                                                                                                                                                                                                                                                                                                         | No pisan reglas personalizadas de un municipio y son repetibles; una bolsa recibía «ponle la tapa».                                                             |
| ADR-22 | PWA con `vite-plugin-pwa` (`registerType: 'prompt'`, manifiesto en `src/pwa/manifest.ts`, _NetworkOnly_ para `/api/*` en cualquier origen); íconos generados por `npm run icons` desde tres SVG (logo, maskable a sangre con contenido al 80 %, favicon solo hoja) y versionados; sin red, `OfflineBanner` es el único aviso (`ServiceStatus` se oculta) y «Escanear residuo» queda con `aria-disabled`                                                                                                                                                                                 | Nunca cachear escaneos ni fotos; actualizar sin recargas sorpresa; un favicon legible a 16 px; sin mensajes de conexión contradictorios.                        |
| ADR-23 | Upcycle: la IA devuelve `can_upcycle` y `material`; el backend bloquea las ideas si `material` es `peligroso`/`electronico` o `objectName` tiene un término bloqueado (por palabra, sin tildes, con plural; «aceite» no), con `warn` en el log. Exactamente 3 ideas (más → recorta; menos → reintento → `AI_BAD_RESPONSE`), recortes en palabra completa y `max_tokens` 384 (≈ 250 de salida)                                                                                                                                                                                           | Nunca proponer manualidades con peligrosos, sanitarios o vidrio roto aunque la IA se equivoque; un falso positivo solo sugiere Clasificar.                      |
| ADR-24 | Modo de escaneo en Zustand solo en memoria (Clasificar al abrir, se conserva en la sesión). `photoStore` guarda la última respuesta de cada modo con el `id` de la foto; `useScan` la reutiliza, «Reintentar» la salta y `setPhoto`/`clear` la borran. Nada de fotos ni respuestas en el almacenamiento del navegador                                                                                                                                                                                                                                                                   | Volver entre `/ideas` y `/resultado` no gasta llamadas a la IA; la foto no persiste en el dispositivo por privacidad.                                           |
| ADR-25 | Chat (HU-10/11): la idea del cliente no es confiable (límites de upcycle y respaldos de `upcycle.safety.ts` sobre `objectName`/`title` → `422 UNSAFE_REQUEST` sin IA); se aceptan ≤ 50 mensajes y a la IA van los últimos 10; respuesta en texto plano; limitador 20/min y JSON ≤ 64 KB en `/chat`; el hilo vive en `photoStore.chats` (memoria) por idea y se borra con foto o ideas nuevas                                                                                                                                                                                            | Control de costos y de abuso sin romper el hilo del cliente; nunca guiar algo peligroso aunque el cliente manipule la idea; privacidad.                         |
| ADR-26 | Auth (HU-04): el backend valida el JWT con `supabase.auth.getClaims(token)` (JWKS local si la firma es asimétrica; `getUser()` con HS256), inyectable como `TokenVerifier`. `optionalAuth`: sin cabecera → anónimo; cabecera mal formada, token inválido o vencido → 401; caída o 5xx de Auth → 500. Frontend con PKCE y `?volver=` solo con rutas internas. Ante un 401 con token, el cliente llama a `refreshSession()` y reintenta una vez con el token nuevo o, si no renueva, cierra la sesión local y reintenta anónimo                                                           | Sin secreto JWT en el servidor y sin llamada de red por petición con claves asimétricas; una sesión revocada nunca impide escanear; sin redirecciones abiertas. |
| ADR-27 | Historial (HU-13): con sesión, `/scan/*` guarda imagen (`scan-images/<user_id>/<scan_id>.jpg`), fila en `scans` con `result` jsonb (copia de lo que vio el usuario) y `scan_ideas` con ids generados en el backend (`ideaId` en la respuesta); si falla, se deshace y se responde `saved: false`. Lectura siempre filtrada por `user_id` (id ajeno o mal formado → 404), orden `created_at desc, id desc`, URLs firmadas de 10 min en lote; filas con `result` inválido se omiten de la lista con `warn` (solo id). Chats de ideas guardadas con clave `historial:<scanId>:<ideaIndex>` | El detalle no gasta IA ni cambia con las reglas; la service role salta RLS; paginación estable; una fila corrupta no tumba el historial.                        |
| ADR-28 | Favoritos (HU-12): el cliente solo envía `ideaId`; el backend arma la copia desde `scans` + `scan_ideas` con join por `scans.user_id` (ajena → 404) y `POST` es idempotente (200 con la existente, carrera por `unique (user_id, idea_id)`). `GET /history/:id` añade `favoriteId` por idea. En el cliente, un store Zustand en memoria `ideaId → favoriteId` compartido por `/ideas` y el historial, vaciado al cambiar de usuario; `photoStore` recuerda si cada respuesta se pidió con sesión para ofrecer «Guardar este escaneo»                                                    | Nunca confiar texto del cliente; el corazón sobrevive a la caché de `/ideas`; distinguir «sin sesión» de «falló al guardar».                                    |
